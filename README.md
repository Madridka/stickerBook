# Вклейка

«Вклейка» — цифровой альбом футбольных карточек с игровым циклом от получения очков и открытия наборов до подготовки и вклейки наклеек.

Текущая версия: `1.13.0` · статус: **alpha**.

## Возможности

- кликер с энергией на 100 действий, восстановлением в течение двух часов и линейным бонусом до +50% за прогресс альбома;
- магазин наборов для разных журналов и восемь случайных мини-игр для получения бесплатного блистера с интервалом в четыре часа;
- сохранённые сессии открытия наборов по пять карточек без потери наград после перезагрузки;
- Drop Engine V2 с редкостями, настраиваемыми шансами и индивидуальными весами карточек;
- независимая для каждого альбома late-game pity-система: на поздней стадии заполнения следующий подходящий набор гарантирует пополнение коллекции после случайно выбранной серии из двух–шести наборов без новой карточки;
- коллекция с поиском, фильтрацией, сортировкой, просмотром, мягким удалением и учётом оригиналов и повторов;
- обмен пяти повторов на одну из пяти случайных карточек с сохранением незавершённого выбора;
- рейтинг игроков по общему числу карточек и отдельным журналам с публичными профилями и статистикой коллекции;
- интерактивный альбом ЧМ-2026 с оглавлением, перелистыванием, прогрессом и страницами всех 48 сборных;
- альбом UCL 2026/27 с 560 карточками 28 клубов, реальными эмблемами, портретами и зафиксированными источниками медиа;
- альбом «История Томи» со 100 карточками пяти футбольных эпох;
- журналы клубных эмблем: 496 клубов Испании, 125 клубов России, включая 16 клубов МФЛ, и 795 клубов Англии на десяти уровнях футбольной пирамиды;
- трёхэтапная подготовка наклейки и свободная вклейка с сохранением качества, смещения и угла;
- совместное хранение обычных и особых версий игрока в одном слоте с выбором отображаемой карточки;
- типизированный каталог schema v2 для 48 сборных, WebP-подложки всех страниц, полные составы всех стран;
- аккаунты с входом и регистрацией, Fastify/SQLite-сервером, локальной копией прогресса и безопасным объединением изменений между устройствами;
- OpenAPI 3.1 и Swagger UI для серверных маршрутов, автоматические online-бэкапы SQLite с ротацией;
- защищённая web-админка для просмотра прогресса, редактирования сохранений, выдачи предметов, диагностики pity и ручного создания резервных копий;
- просмотр форматированного JSON локального сохранения прямо на экране авторизации;
- локальное хранение баланса, энергии, наборов, коллекции и прогресса альбома в IndexedDB с синхронизацией после авторизации;
- одноразовая цепочка первых шагов от заработка монет до бесплатного набора, автоматически сверяемая с игровыми данными и сохраняемая в IndexedDB.
- универсальные долгосрочные цели на `/goals`: категории, последовательные ступени, вычисляемый прогресс, отдельное получение наград и компактный блок ближайших целей на главной.
- постоянная панель ресурсов в шапке показывает монеты и энергию на всех экранах, а обучение явно проводит от выбора карточки к автоматическому запуску её подготовки.

## Мини-игры за блистер

При каждом запуске из доступного пула случайно выбирается одна из восьми игр:
поиск сигнала, извлечение блистера из стойки, автомат с блистерами, поиск пака
после перемешивания, пазл карточки, ловля падающих паков, запоминание карточек
или повтор комбинации пасов.

«Запомни карточки» использует реальные карточки игроков редкости `epic` и
`legendary` из общего каталога ЧМ-2026. В «Повтори комбинацию пасов»
последовательность растёт от трёх до пяти шагов; зарегистрированные нажатия
подсвечиваются и получают номера, поэтому порядок ввода остаётся видимым.

## Система целей

Статические definitions находятся в `src/features/goals/goalDefinitions.ts`, а чистый
resolver прогресса — в `goalProgressResolver.ts`. Коллекция, редкость, варианты,
подготовка и заполнение журнала вычисляются из актуальных карточек. Исторические
значения заработанных монет, купленных и открытых наборов, завершённых мини-игр и
обменов сохраняются как устойчивые счётчики.

Dexie хранит `goalStates` (`completedAt`, `claimedAt`) и `goalCounters`; тексты,
награды и targets остаются в коде. Получение награды
выполняется единой транзакцией вместе с проверкой `claimedAt`, обновлением баланса
и добавлением наборов. Guided Game Loop остаётся отдельным onboarding-state и не
смешивается с долгосрочными целями.

## Игровой цикл

Главная страница подсказывает наиболее полезное действие по текущему состоянию: продолжить
незавершённое открытие, вклеить подготовленную наклейку, открыть или купить набор, сыграть
за бесплатный набор, обменять повторы либо заработать монеты. Когда энергия закончилась,
кликер приглушается, показываются оба таймера восстановления, а действия без затрат энергии
остаются доступными. Выбор карточки в коллекции открывает её разворот в журнале, поднимает
карточку в начало трея и ненадолго выделяет её, не запуская подготовку автоматически.

## Аккаунты и серверное сохранение

Fastify-сервер хранит пользователей, сессии и версионированные снимки Dexie в локальном
файле SQLite `server/data/sticker-book.sqlite`. Пароли сохраняются только как `scrypt`-хеши,
а браузер получает случайную `HttpOnly` cookie-сессию.

Сервер предоставляет проверку состояния `/api/health`, регистрацию, вход, выход и
восстановление сессии через `/api/auth/*`, а также чтение и версионированную запись снимка
через `/api/save`. Параметры адреса, порта, SQLite-файла и защищённой cookie задаются в
`.env`; перечень поддерживаемых переменных находится в `.env.example`.

OpenAPI-схема и Swagger UI доступны по `/api/docs/openapi.json` и `/api/docs` только в
development-режиме либо при явном включении. В production документация по умолчанию закрыта.
Авторизация игровых методов выполняется через HttpOnly cookie, административных — через HTTP Basic.

### Web-админка

Сервер содержит отдельную админку по адресу `/admin`. Она показывает список аккаунтов,
дату регистрации и последнего сохранения, монеты, энергию, карточки, дубли, наборы, цели и
прогресс по каждому альбому. В карточке пользователя доступен полный JSON сохранения;
изменения записываются как новая версия и защищены от перезаписи более свежего сохранения.
Через форму «Выдать предмет» можно добавить карточку или один из игровых паков без ручного
поиска нужной таблицы в JSON. Повторно выданная карточка автоматически попадает в дубли.
Тип блистера выбирается готовым вариантом, а совместимый альбом назначается автоматически.
Старые некорректные пары `packId`/`albumId` можно исправить кнопкой в карточке пользователя.
Там же отображается pity-state каждого альбома и доступно ручное создание резервной копии БД.

Доступ включается только при наличии `scrypt`-хэша пароля. Открытый пароль в конфигурации
запрещён; безопасный интерактивный генератор находится в `scripts/hash-admin-password.ts`:

```dotenv
STICKER_BOOK_ADMIN_USERNAME=admin
STICKER_BOOK_ADMIN_PASSWORD_HASH=<generated-scrypt-hash>
```

Авторизация админки независима от игровых аккаунтов и использует HTTP Basic. Без заданного
пароля страница и административные API отвечают как несуществующие. Для внешнего доступа к
админке обязательно используется HTTPS.

### Резервные копии SQLite

При включённых бэкапах сервер создаёт согласованную копию SQLite при запуске и затем по
расписанию. Используется online-backup API SQLite, поэтому основной файл не копируется
напрямую во время активной WAL-сессии. Старые копии удаляются только из выделенного каталога
и только после превышения лимита хранения.

```dotenv
STICKER_BOOK_BACKUP_ENABLED=true
STICKER_BOOK_BACKUP_DIRECTORY=server/data/backups
STICKER_BOOK_BACKUP_INTERVAL_HOURS=24
STICKER_BOOK_BACKUP_RETENTION=14
```

Подробные маршруты и эксплуатационные процедуры описаны в
[`docs/server-operations.md`](docs/server-operations.md).

Для локальной разработки скопируйте `.env.example` в `.env` и запустите клиент и сервер
одной командой:

```bash
npm run dev
```

Интерфейс будет доступен на `http://localhost:4040`, API — на `http://localhost:4041`.

Для запуска собранного приложения с одного процесса:

```bash
npm run build
npm start
```

После сборки сервер раздаёт интерфейс и API на `http://localhost:4041`. В локальной сети
можно открыть `http://<IP рабочего компьютера>:4041`. Для публикации в интернете нужен
HTTPS reverse proxy. Безопасный production-режим используется по умолчанию: cookie получает
флаги `Secure`, `HttpOnly`, `SameSite=Lax`, а отладочные маршруты и подробное логирование выключены.

При первой регистрации можно перенести текущий локальный прогресс в новый аккаунт.
Последующие входы загружают сохранение аккаунта, а неотправленные офлайн-изменения того же
пользователя объединяются с актуальной серверной копией. Если два устройства изменят одну версию одновременно,
клиент получит новый снимок и объединит его с локальным вместо молчаливой потери прогресса.
Для неавторизованного пользователя приложение всегда открывает единый экран входа и
регистрации. Кнопка «Показать JSON сохранения» отображает доступный на устройстве снимок
Dexie; этот же снимок отправляется на сервер, когда при регистрации включён перенос
прогресса. Ручной импорт JSON не выполняется, поэтому просмотр не изменяет игровые данные.
